# Workspace

## Overview

pnpm workspace monorepo using TypeScript. 국립한국교통대학교 RISE 성과관리 시스템 — a Korean-language performance management system for the RISE program.

## Stack

- **Monorepo tool**: pnpm workspaces
- **Node.js version**: 24
- **Package manager**: pnpm
- **TypeScript version**: 5.9
- **API framework**: Express 5
- **Database**: PostgreSQL + Drizzle ORM
- **Validation**: Zod (`zod/v4`), `drizzle-zod`
- **API codegen**: Orval (from OpenAPI spec)
- **Build**: esbuild (CJS bundle)
- **Frontend**: React + Vite, shadcn/ui, Recharts, TanStack Query

## Key Commands

- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- `pnpm --filter @workspace/api-server run dev` — run API server locally

## Artifacts

- `artifacts/api-server` — Express API server (port 8080, path prefix `/api`)
- `artifacts/rise` — React+Vite frontend (port 24368, path `/`)

## Architecture

### Database Schema (lib/db)
- `projects` — RISE 사업 프로젝트
- `tasks` — 단위과제 (project → many tasks)
- `indicators` — 성과지표 (task → many indicators, supports parent/child hierarchy)
- `indicator_targets` — 연차별 목표값
- `indicator_results` — 실적 입력 + 진척도 + 자체평가 + 검토상태
- `evidence_files` — 증빙자료 (result → many files)
- `reviews` — 검토 이력
- `feedback_actions` — 자체평가 및 환류계획
- `users` — 사용자 (role: admin, reviewer, manager, reporter)

### API Routes (artifacts/api-server)
All routes prefixed with `/api`:
- `/projects`, `/tasks`, `/indicators`, `/targets`, `/results`, `/reviews`, `/feedback`, `/users`
- `/dashboard/summary`, `/dashboard/projects`, `/dashboard/tasks`, `/dashboard/alerts`, `/dashboard/trend`

### Frontend Pages (artifacts/rise)
- `/` — 대시보드 (진척도 요약, 차트, 알림)
- `/projects` — 프로젝트 관리
- `/tasks` — 단위과제 관리
- `/indicators` — 지표 관리 (상위/하위 지표)
- `/targets` — 목표값 관리
- `/results` — 실적 입력 (작성/제출)
- `/reviews` — 검토 관리
- `/feedback` — 자체평가·환류
- `/users` — 사용자 관리

### Important Notes
- **Date serialization**: All routes use `serialize()` from `lib/serialize.ts` to convert Drizzle `Date` objects to ISO strings before Zod `.parse()`. Without this, Zod schemas generated by Orval throw `expected string, received date`.
- **Default year**: All frontend pages default to `2025` (latest seeded year). Seed data covers 2023–2025.
- **Orval config**: zod output uses `mode: "single"` — no `schemas` option. This prevents TS2308 export conflicts.
